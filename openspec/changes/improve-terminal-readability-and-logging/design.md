# Design

## Context

问题动机见 `proposal.md`。`main.main()` 当前将根日志的 INFO 及以上内容输出到 stderr；LLM 模块已共用 `llm_murder` logger，并已产生请求用量、耗时、校验结果、重试与降级信息。`--record` 仅在终局按需保存公开 JSON，不能覆盖中途退出前的诊断留档。

`TerminalUI._print_event()` 当前将正式发言整体设为 `white`，等待函数在临时状态外另打印一次姓名；`Controller.on_speech()` 每次调用都会打印两行状态。正式发言事件已经包含编号、姓名、座位、正文和窗口字段，无需改变引擎事件。

已有的 `bound-game-context-and-generation` change 实现了请求分类和安全指标；本 change 消费这些信息，不重新实现预算或分类。现有配置目录为 `~/.llm_murder/`，日志路径可直接复用这个位置。

## Goals / Non-Goals

**Goals:**

- 在现有追加式终端界面内完成调整，保留正式事件、角色视角和输入方式。
- 将日志初始化和释放限制在交互式入口，本地日志与公开记录各自独立。
- 用标准库及现有 Rich 功能完成，确保无颜色时依旧可读。

**Non-Goals:**

- 不增加固定全屏面板、主题系统、调试开关或配置项。
- 不新增遥测上传、原始请求抓包、模型输出存档、日志查看器或自动清理策略。
- 不改自动对局脚本的诊断输出、LLM 行动预算、事件内容或公开记录格式。

## Decisions

### 1. 在 UI 中格式化正式发言

从正式事件的结构化字段组装 Rich `Text`：标题包含 `[#编号] 姓名（座位） · 窗口`，采用 `bold cyan`；正文另起一行，沿用终端默认前景色，不设置 `white` 或 `dim`。发言块之间留空行。只处理正式 SPEECH 事件，人类与 AI 共用路径；正文使用纯文本以保留引用、方括号及多行内容。

等待期间将姓名与“正在组织发言…”放入同一个临时 `Live` 状态，完成或异常时整体清理，不留下多余的无编号姓名行。只有校验后的正式事件展示正文，沿用现有编号与去重逻辑。

选择独立标题与正文是为了利用已有事件字段控制层次。整段加粗难以区分说话人与内容；为每条发言套面板会增加边框和滚屏量，因此不采用。

示意：

```text
[#12] 学姐（6号） · 首轮发言
我更怀疑3号，昨天的投票和今天的说法对不上。

[#13] 阿飞（1号） · 首轮发言
我解释一下昨天为什么改票。
```

### 2. 按状态变化展示摘要

每个 `TerminalUI` 实例仅保存最后展示的摘要值，比较板子名称/版本、阶段、存活名单与警长。让现有增量渲染入口在摘要首次出现或变化后更新；移除 Controller 中每次发言前的无条件重复输出。摘要在决策输入前刷新，正式事件和私有提示照常增量展示。

缓存只影响摘要的展示频率，不改变事件游标或游戏状态。采用内容比较即可覆盖死亡、阶段和警长变化，无需引入通用状态管理器或重新设计座位面板。

### 3. 日志由主入口创建，逐条写入

在建局前建立 `~/.llm_murder/logs/`，复用标准库安全文件创建能力生成含时间戳和唯一后缀的 `.log` 文件；新建目录权限为 700，文件为 600。使用 UTF-8 的标准库文件 handler，记录 INFO 及以上应用诊断，沿用现有时间、级别和消息格式。逐条刷新，不等待终局，不承诺断电后未写完记录的持久性。

将当前面向 stderr 的应用诊断配置改为文件输出，并避免应用日志再次传播到终端；第三方 SDK/HTTP 的常规请求日志不进入游戏终端，也不启用会记录请求正文的 DEBUG。技术日志和 UI 提示各走现有通道，终局统计继续保留原有内容。

在建局完成后记录板子、模型、命令行种子和运行模式，在退出路径记录正常结束、用户中断或异常类型；终局及中途退出提示实际日志路径。异常日志仅保存异常类型和提取后的调用栈位置，不直接序列化异常正文、局部变量或请求对象。

正常结束和异常退出均在 `finally` 中刷新、关闭并移除本次 handler，恢复本次入口改变的 logger 状态；不要调用会关闭其他使用者 handler 的全局清理。日志创建和释放只发生在主入口，直接调用 `build_game()`、导入模块和自动对局脚本不会额外创建日志。

相比将日志并入 `--record`，独立逐条落盘可以覆盖未启用导出和中途退出的对局，也无需改变公开记录格式。相比在仓库当前目录创建文件，沿用用户配置目录可以支持从任意工作目录启动。

### 4. 复用已有诊断，保持内容边界

复用 `LLMClient` 的请求指标与现有截断、校验、重试、压缩和降级日志，不增加另一套请求追踪模型。检查现有错误消息的插值来源：日志仅保留分类、必要字段位置及非敏感说明，不将模型生成的字段名、候选正文、API 错误正文或私有内容带入持久化错误描述。仅在发现相关日志点不满足这个边界时修正它们。

玩家输入错误、角色私有信息、公开事件及记录保存失败仍由 UI 展示；无法继续游戏时展示简短原因和可用的日志路径，以失败状态退出。隐藏的是过程技术详情，保留既有安全降级行为和 Ctrl-C 退出状态。

### 5. 日志故障不阻断对局

日志目录或文件无法创建时，输出一次简短提示并停用本局文件日志。运行中写入或刷新失败时，同样只提示一次，停用失败 handler，保留已写文件并标记其不完整，禁止标准日志错误处理把完整 traceback 或原日志内容刷到终端。

终局仅对可用日志显示正常保存路径，对部分写入后失败的文件明确标注记录不完整。无需增加备用目录、持续重试或回退到详细终端日志。

## Risks / Trade-offs

- 不同终端对强调色的实际观感不同 → 正文沿用默认前景色，标题同时依赖加粗、文本标签和换行，并验证深色、浅色与无颜色输出。
- 状态缓存可能漏掉更新或继承上一局 → 比较所有实际展示的字段，缓存限定到 UI 实例，测试死亡、阶段及警长变化和新局初始化。
- 持久化错误描述可能间接带出私有内容 → 验证日志插值来源，增加密钥、私有策略和失败候选哨兵测试，不开启 SDK 调试正文。
- 日志设置影响同进程后续运行 → 清理仅限本次 handler，测试重复入口及异常路径，不改导入时的全局日志状态。
- 每局一个文件会逐渐占用本地磁盘 → 在 README 中说明目录及手动删除方式；本次不增加自动清理规则。
- 日志写入失败后无法保证完整诊断 → 一次提示并标识不完整，保证游戏继续，保留已经写入的内容。

## Migration Plan

无需配置或数据迁移。合入后交互式启动自动启用新显示与本地日志；更新 README 中“正常游戏逐请求打印指标”的说明，保留 `--record` 文档及终局统计说明。回滚时恢复入口和 UI 改动即可，既有公开记录与本地日志无需修改。

# Spec Delta

## Purpose

为交互式狼人杀对局自动保存本地运行诊断，使玩家在正常结束或中途退出后仍可检查请求指标和失败原因，同时避免技术日志打断游戏阅读或保存密钥、角色私有信息及模型原始内容。

## ADDED Requirements

### Requirement: 自动创建独立运行日志
交互式游戏入口 SHALL 在建局前自动为本次运行创建 `~/.llm_murder/logs/` 下的独立 UTF-8 日志，无需指定额外参数或启用公开记录导出。日志文件 MUST 使用唯一名称且不覆盖已有文件；在支持 POSIX 权限的平台，新建日志目录及文件 SHALL 分别仅允许当前用户访问。

#### Scenario: 正常启动并保存日志
- **WHEN** 玩家未指定公开记录导出参数而启动一局游戏
- **THEN** 系统自动创建独立日志，在游戏结束时提示实际日志路径

#### Scenario: 多次启动不覆盖
- **WHEN** 同一时间附近启动多次游戏且日志目录中已有文件
- **THEN** 每次运行使用不同文件，已有日志内容保持不变

#### Scenario: 离线模式
- **WHEN** 玩家以离线演示模式启动游戏
- **THEN** 系统同样创建日志并记录离线模式和退出状态，不伪造真实 API 请求用量

### Requirement: 安全诊断记录
日志 SHALL 保存时间、级别、板子、模型、启动时指定的随机种子及运行模式，并复用现有请求序号、估算与实际输入输出、思考与缓存 tokens、耗时、结果分类、校验结果及重试和降级原因。日志 MUST NOT 包含密钥、完整提示词、角色私有事件、AI 私有策略、原始模型输出或服务端错误正文。

#### Scenario: 请求重试后成功
- **WHEN** 一个行动发生输出截断或校验失败，经重试后成功
- **THEN** 日志可检查各次已有请求指标、失败分类与最终校验结果，不包含失败候选正文

#### Scenario: 持续失败安全降级
- **WHEN** 一个行动达到现有重试限制并采用安全行为
- **THEN** 日志保留非敏感的失败分类和降级原因，游戏终端只显示正常游戏事件或中性兜底发言

#### Scenario: 响应中含敏感内容
- **WHEN** 错误正文或无效结构化响应包含密钥、私有策略或原始候选文本
- **THEN** 日志仅保存允许的分类、字段位置或统计，不将敏感内容随错误描述写入文件

### Requirement: 增量留档与退出记录
日志 SHALL 随运行逐条写入并刷新，而非仅在终局导出。正常结束、用户中断及未恢复异常退出时，系统 SHALL 记录相应退出状态并释放本次日志资源；异常记录 SHALL 限于异常类型和不含异常正文、局部变量的调用栈位置。已经写入的记录 MUST 在退出后保留。

#### Scenario: 中途主动退出
- **WHEN** 玩家在游戏进行中使用 Ctrl-C 退出
- **THEN** 之前的日志仍可读取，退出状态及日志位置得到提示，游戏保持现有用户中断退出语义

#### Scenario: 未恢复异常退出
- **WHEN** 游戏因未恢复异常停止且日志仍可写入
- **THEN** 日志保留已写记录和安全的异常位置，终端给出简短失败提示及日志路径，并以失败状态退出

#### Scenario: 同一进程重复运行入口
- **WHEN** 同一进程先后启动并结束两次游戏入口
- **THEN** 两次日志相互独立，记录不重复写入，也不写入已结束运行的文件

### Requirement: 日志不可用时继续游戏
创建、写入或刷新日志失败时，系统 SHALL 给出一次简短的“本局诊断日志无法保存”提示，并允许游戏继续。系统 MUST NOT 将详细诊断改为持续输出到游戏终端，也 MUST NOT 将不可用日志宣称为已完整保存。

#### Scenario: 日志目录不可写
- **WHEN** 创建日志目录或文件时遇到权限错误
- **THEN** 终端提示本局无法保存诊断日志，仍能进入游戏，终局不显示日志保存成功

#### Scenario: 运行期间写入失败
- **WHEN** 已建立的日志在游戏过程中因磁盘或其他文件错误无法继续写入
- **THEN** 系统提示一次日志保存失败，后续不重复刷出日志错误或完整 traceback，并继续正常游戏交互

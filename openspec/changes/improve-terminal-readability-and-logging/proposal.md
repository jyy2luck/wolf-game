# Proposal

## Why

游戏过程中的请求指标、校验与重试日志和正式发言混在终端中，发言缺少清晰的视觉层次，重复状态信息进一步打断阅读。需要让玩家优先看到对局内容，同时自动保存本地诊断信息，方便事后定位问题。

## What Changes

- 正式发言采用独立标题与正文：突出姓名、座位、发言编号及窗口标签，正文使用终端默认前景色，相邻发言留空行。
- 生成期间仅显示短暂等待状态；请求指标、校验失败、重试与安全降级详情默认移出游戏终端。
- 存活名单和阶段状态仅在首次展示或内容变化时更新，保留正常游戏事件、角色私有提示与玩家操作错误。
- 每局自动在 `~/.llm_murder/logs/` 创建独立日志，逐条保存安全运行元信息、现有请求指标与错误分类，中途退出也保留已写内容。
- 保留现有终局胜负、身份回顾和完整 LLM 用量、重试、降级统计，并提示实际日志位置；日志不可用时简短提示并继续游戏。

## Capabilities

### New Capabilities

- `runtime-diagnostics`: 游戏入口的本地日志生命周期、安全记录范围、异常退出留档及日志不可用提示。

### Modified Capabilities

- `terminal-ui`: 正式发言的视觉层次、变化时更新的状态摘要、过程诊断隐藏及保留终局统计与必要错误提示。

## Impact

涉及 `ui/terminal.py`、`main.py`、终端与入口日志测试，以及 `README.md` 的诊断说明。复用标准库 `logging`、现有 `llm_murder` logger、请求指标和配置目录；必要时收敛现有日志消息的内容，不改变 LLM 请求协议、引擎事件、公开记录格式或调用预算，不增加依赖和用户配置项。

# Design

## Context

见 proposal.md。固定六人、两狼，事件流已隔离角色视角；五种行动各有一次请求和三次结构化尝试预算。现有私有摘要只有发言会更新，策略检索只使用粗粒度标签。

## Goals / Non-Goals

**Goals:** 让确定事实和主观判断持续驱动行动，同时保留欺骗空间和兼容旧响应。

**Non-Goals:** 不增加依赖、独立规划请求、跨局记忆或强制最优裁决；离线测试不声称证明实战胜率。

## Decisions

### 1. 在现有局面函数闭合硬事实

使用公开初始狼数枚举兼容的狼座位组合，应用已知阵营和当前判胜约束，交集认证必为狼，候选并集之外认证好人。规则不适用、资料矛盾时不闭合。固定六人只有十五种初始狼对，无需通用求解器。

### 2. 将声明场景与硬认证分开

从有编号的公开原文提取明确的第一人称身份、查杀和金水声明，否定、转述和假设不触发。声明表用于提示和策略标签，不进入硬事实集合。歧义保留原文供模型判断，使用 paired cases 验证解析边界。

### 3. 复用私有摘要和一次行动调用

投票、查验、狼刀及用药包增加可选 private_strategy，成功校验后提交；旧包缺省保留上一份摘要。输出任务要求比较依据和后果，首轮上限 240 字符、回应 150 字符；技能与投票使用较低温度，发言保留原有风格。DeepSeek 自动思考默认 enabled，用户显式模式优先。

### 4. 狼队计划通过私有事件共享

狼刀目标包额外返回可选 team_plan；Controller 仅在调用成功后将计划写为狼队私有事件，下一行动读取最新计划。队友个人摘要始终隔离。人类自己选刀时沿用原流程，不增加请求。

### 5. 固定一轮回应和投票屏障

沿用同一环状顺序，增加一次回应，每轮提供独立进度。事件附带轮次且编号全局递增。所有投票收集完毕才记录个人票型，保留旧总票数构造调用。事实校验仅针对明确个人投票句式，并保留预测及反驳转述。

### 6. 用现有统计及公开记录提供证据

UsageStats 增加结构化重试和降级计数；记录选项在终局写一份 JSON，排除全部私有事件和候选，使用独占创建防覆盖。验证包含固定残局、声明边界、摘要更新、共享计划隔离、回应进度及票型屏障，并执行现有回归。

## Risks / Trade-offs

- [思考及回应增加延迟和费用] → 保留显式关闭思考；回应保持简短，不追加规划请求。
- [自然语言声明漏识别] → 只处理明确句式，展示完整历史；误检和漏检用成对用例约束。
- [主观策略泄露或变事实] → 计划独立标记为策略，摘要不进入事件或记录，真假判断仍由硬事实限定。
- [候选空集导致错误认证] → 无兼容组合时不使用交集或并集推导。

## Migration Plan

旧配置、旧 JSON 与旧票型构造保持兼容，默认行为随代码升级生效。无需修改本机配置文件，无数据迁移；回滚代码即可恢复原规则。

# Design

## Context

引擎串行调用 AI，事件日志已按视角隔离，原始事件还用于事实校验。参见 proposal.md 的问题说明。

## Goals / Non-Goals

目标是在共享调用管道落实预算且不改变引擎规则。无需远端会话、向量库或摘要模型。

## Decisions

- 保留完整日志与现有策略摘要。上下文块采用程序生成的原文节选，保留事实和来源，近期六条原文优先；压缩时省略重复板子、阶段与昼夜分隔标签，保留最新狼队主观计划；不使用可能将谎言认证为事实的生成式摘要。
- 使用无依赖估算（中文偏保守、ASCII 按字符折算），配置默认输入软上限 12000、行动总时限 90 秒。可选模型窗口必须来自用户核实；扣除当前输出预算和安全余量。依据服务实际 usage 向上校准估算。
- 按编号回查至多三条公开原文，每行动至多一次，共享三次请求。验证始终基于完整 view。
- 保留同步游戏接口，内部复用 AsyncOpenAI 与 asyncio.Runner，以 asyncio.timeout 取消包括流式读取在内的整个请求。统一的行动 deadline 覆盖重试与退避。
- 网络、上下文超限、输出截断、格式/事实错误共用三次实际请求额度；输出扩容限于本行动。不可重试的 4xx 立即停止。失败日志只保存分类和计数，不保存服务返回正文。
- DeepSeek 及显式配置 thinking 的兼容端点均强制 disabled；其他兼容端点不发送未知扩展参数。

## Risks / Trade-offs

- token 估算不是模型分词 → 留安全余量并使用实际 usage 向上校准；真实超限再缩减一次，无法容纳固定信息时透明降级。
- 节选损失细节 → 保留编号、有限原文回查及完整日志校验；不承诺任意长局永不降级。
- 不同提供方参数支持不同 → 保留 JSON 与 thinking 的端点兼容边界。
- 实测受网络和模型负载影响 → 报告实际分布和错误，不作恒定速度承诺。

## Migration Plan

旧配置无需重写。新增字段有默认值，enabled 为兼容字段但运行时忽略。移除本次代码即可回滚，无事件数据迁移。

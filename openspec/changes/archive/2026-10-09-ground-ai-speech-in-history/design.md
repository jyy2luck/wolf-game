# Design

## Context

动机见 proposal.md 的 Why。现有事件流已经保存整局历史，事件包含 day、seat、speech_index 和原文，视角过滤没有按天裁剪；需要增强其表达与使用约束，而不是另建记忆系统。

当前 `render_memory` 直接拼接事件文本，单条发言没有显式天数；`build_speech_prompt` 不知道实际发言顺序。`day_speech` 在结构化输出的校验中只验证怀疑目标，泄密重试另起一轮结构化调用，且原始流式增量已经通过回调进入终端。

本设计涉及游戏调度、AI 上下文、输出校验和终端展示，复用现有 Python、pydantic、事件流与客户端。具体行为合同见三个能力的 delta specs。

## Goals / Non-Goals

**Goals:**

- 使用引擎事实构建发言进度和整局历史索引，让今日进度与历史证据同时存在。
- 对可确定的引用错误、无记录发言行为和时间错置给出可复现的拒绝原因。
- 校验覆盖最终公开文本，拒绝候选不进入界面或事件，纠正与降级有统一上限。
- 保留六人局的人设、身份伪装、主观怀疑和既有角色视角隔离。

**Non-Goals:**

- 不新增数据库、向量检索、跨对局长期记忆或历史压缩；本局全部可见历史直接提供给模型。
- 不增加每次发言的独立 LLM 审核请求，不把自由中文的任意语义一致性包装成可由正则完全证明的能力。
- 不改变角色配置、胜负、死亡起点、平安夜、多死者时的既有发言排序规则，也不新增他人个人投票记录的公开机制。

## Decisions

### D1. 发言进度由实际调度生成

在 `engine/game.py` 构造公开的发言上下文值对象，包含 day、当前 speaker、完整 order、当前位置、spoken、remaining，以及公开座位姓名映射。`spoken` 表示今日已完成正式发言，`remaining` 表示当前发言人之后的玩家；当前发言人单独标记，避免“已发言”和“待发言”的含义重叠。

上下文从 `_play_day` 实际使用的 speakers 及其当前位置生成，通过发言回调传给 Controller，再传到 AI 的发言方法与提示词。更新相应回调类型和测试桩，不在 AI 层复制排序算法或从存活座位猜测顺序。每天重新计算进度，整局 events 不重置。无完整上下文的直接调用可以从当天正式事件推导已发言集合，但不虚构未知的完整顺序。

备选：只靠提示词从死讯推导顺序，会在平安夜或既往放逐起点等场景中产生偏差，因此不采用。

### D2. 完整历史与当日进度分别表示

`render_memory` 按原有事件顺序渲染全部可见记录，为每条记录标记天数、昼夜及来源类型。公开发言格式表达为“第 1 天 · 玩家发言 [#3] 2 号：原文”，系统公开事实和当前角色私有事实分别标记。实际 day、seat、speech_index 与 extra.content 作为事实索引来源，不通过重新解析玩家自由文本构造行为记录。

近期自身发言摘要可以保留，但必须带时间信息，并且不替代完整记忆。发言、投票和夜间技能都复用这一渲染路径；出局玩家的公开发言仍保留。新局使用新的事件集合和 AI 状态，不串局。

提示词明确：真实记录只证明某人说过该话；其中指控、身份声明和推测不能自动升级为系统事实。“今天尚未轮到”只描述今天进度，不能否定往日记录。公共票型只有总得票数时，不推断其他人的个人投票目标；自身投票仍来自已有 my_votes。

备选：只提供今天记录或最近三条，会丢失用户明确要求的跨轮次线索，因此不采用。

### D3. 引用依据与正文一起生成并确定性核对

为发言包增加 `references` 列表，默认空列表以兼容旧的无引用包。每项包含 `speech_index`、`seat`（对外 1-based）、`day`、`quote`（非空原文片段），提示词提供合法 JSON 示例。模型不需要另起一次调用生成依据，依据字段不在终端展示。

在每次发言调用开始时，从整局可见的公开 SPEECH 事件构建编号索引。校验包括：

1. 正文中的每个 `[#n]` 都有对应依据，每份依据都在正文中实际使用。
2. 编号真实存在，seat 与 day 精确匹配该记录，quote 是对应原文的实际片段。
3. 正文明确关联的发言人和时间与所引记录一致；不只检查隐藏依据，避免正文说 2 号、依据却指向 6 号。
4. 不因发言人已死亡、今天尚未发言或记录来自往日而拒绝有效依据。

引用编号仅证明来源可追溯，不证明 AI 的主观分析必然正确。引用往日发言时，使用“昨天”“第 N 天”或明确的历史引用上下文；不得将其写成“今天刚才”。原文片段校验不会被其他玩家的转述替代。

备选：只检查编号存在，会漏过张冠李戴和伪造转述；逐轮增加模型审核会增加延迟与成本，且审核本身仍可能出错，因此采用结构化引用和确定性检查。

### D4. 无编号事实断言采用有限的高置信度规则

补充检查明确描述已发生发言行为的句式，包括“某号刚才说了”“一上来就急着说话”“发言太积极”“改口”，以及将正常轮候描述为“故意不说话、躲发言”。识别数字座位及公开姓名，结合当前天数、该玩家整局记录和引用信息判断。

- 没有任何对应记录时，明确断言该玩家已经说过或做过相关发言行为，返回缺少记录错误；“我觉得”不能让不存在的行为变成有依据的行为。
- 只有往日记录时，允许有真实引用的历史分析，拒绝明确声称事情发生在今天的表述。
- 等待、将来、条件假设、“还没听到今天的观点”和无行为断言的主观怀疑不作为已发生事实。
- 有依据地转述“6 号声称 2 号抢话”可以用于质疑 6 号；规则须识别引用或转述范围，不能把被引用的指控误当成当前发言人的事实断言。
- 行为判断与身份判断分开：允许在既有泄密规则内伪装身份、表达怀疑，不拿隐藏的真实身份验证角色表演。

规则只覆盖明确、可测试的冲突，不能用“提到没轮到的人就拒绝”之类宽泛关键词匹配。自由转述与原文是否语义等价依靠来源约束、明确引用和提示词减少错误，保留日志用于后续迭代，不声称已实现完整中文语义证明。

### D5. 一个重试循环完成全部验证

把最终文本规范化、目标合法性、事实检查与泄密检查接入同一次结构化调用的验证阶段，删除泄密失败后重新开启三次尝试的独立循环。首次请求加最多两次重试共享一个计数器，截断扩容也消耗同一尝试预算；客户端原有网络传输重试继续由客户端管理，不另加事实审核调用。

验证结果携带错误类别、具体原因及是否允许继续。泄密违规单独计数，最多一次纠正，第二次即终止。给模型的纠正信息引用实际进度或对应历史记录，例如“2 号整局尚无发言记录”“[#3] 属于第 1 天，不能写成今天”；其他行动的既有格式、目标和截断处理仍保持兼容。

规范化、长度限制和引用校验作用于同一个最终 speech，不能先校验再截掉引用编号或改变意思。失败候选不更新 last_suspect、情绪或事件。最终失败统一返回中性兜底“目前依据不足，我暂时保留判断。”、未定怀疑对象和平静情绪，并将当前 last_suspect 重置为未定；既有正式历史继续保留。

### D6. 校验完成后再公开

保留客户端流式请求能力，白天发言生成期间将原始 delta 缓冲在 AI 内部，不传到终端回调。Controller 的等待上下文只控制发言人和进行中状态；结束后由引擎写入正式事件，再经现有增量事件渲染展示一次带编号的正文。

被拒绝候选、原始 JSON 和 references 都不展示。兜底使用相同事件路径。UI 对 Live 状态的清理须在成功、重试耗尽及客户端失败时都执行，避免残留或重复显示。

备选：原样逐字流式展示后再撤回，会让用户先读到错误内容，不能满足拒绝候选不公开的合同，因此采用等待状态加最终事件展示。终端用户会稍晚看到正文，这是本次明确的展示行为变更。

## Risks / Trade-offs

- [自由中文存在未覆盖的改写、指代和语义冲突] → 严格验证结构化引用并覆盖实际复现句式；正反例同时回归，不以规则匹配替代任意语义判断。
- [规则误伤跨天引用、质疑转述或后置位正常轮候] → 整局索引与今日进度独立，覆盖有效历史引用、引用错误指控进行反驳、等待发言和主观怀疑的允许路径。
- [新增依据字段使输出更长或增加重试] → 引用只携带短原文片段、无引用时为空列表，沿用已有 token 上限与统一重试预算，不新增审核模型。
- [终端取消未经校验的实时正文导致等待感增加] → 保留发言人及进行中状态，最终只展示正式事件，文档明确说明展示时机。
- [长对局的完整历史增加上下文长度] → 当前六人局保留完整记录；超出模型上下文时沿用安全失败路径，不静默裁掉往日发言。本次不增加压缩系统。
- [回调参数及旧测试夹具需要迁移] → 在同一次 apply 中更新引擎、Controller、AI 和测试桩，对缺失引用字段提供解析默认值，已有无引用调用继续可用。

## Migration Plan

1. 在 apply 阶段同步实现公开发言上下文、完整历史标记和引用依据格式，并更新调用点与 mock 输出。
2. 接入统一校验与重试，再切换终端等待及正式事件展示，确保候选内容没有旁路公开。
3. 使用确定性客户端复现用户场景、跨天引用和混合失败；运行相关回归、完整测试及 OpenSpec 严格验证，更新 README。
4. 无持久化数据迁移；若需回退，整体回退本变更的接口、AI 校验和 UI 调整，不能只恢复原始 delta 展示而保留“验证前不公开”的声明。

# Design

## Context

问题证据见 proposal。客户端同时处理流式与非流式请求，agents 通过返回文本进行 schema 与业务校验；现有测试大量替换整个客户端，未覆盖 SDK 响应元数据。

## Goals / Non-Goals

**Goals:** 避免默认高强度思考耗尽预算，针对截断采取有效且有界的重试，兼容旧配置和通用服务，提供不包含密钥或私有思考正文的诊断。

**Non-Goals:** 不调整狼人杀策略、胜负判定或穿帮检测规则。

## Decisions

- 配置增加 `max_tokens=4096`、`max_tokens_limit=16384`、`thinking=null`、`json_mode=null`。`thinking` 可为 enabled/disabled；未指定时 api.deepseek.com 使用 disabled，其他服务遵循服务默认。JSON 模式未指定时仅对 api.deepseek.com 自动开启，其他服务保留兼容参数集。
- 保持 chat 的成功返回类型为字符串。完成原因为 length 时抛出专用截断异常，包含预算、使用量与正文长度；该异常不进入网络重试循环。
- agents 在原有最多三次结构化请求中将截断预算加倍至上限，重试相同有效对话，不回填截断正文。到达预算上限时直接降级；网络重试耗尽也进入安全降级。
- 请求完成后统计 usage，即使正文因截断不可用或服务未返回 usage，调用次数仍准确。
- 所有行动提示词改为合法 JSON 示例，并将字段解释放在示例之外；DeepSeek 的结构化请求默认启用 JSON 模式。
- 使用 httpx MockTransport 和真实 OpenAI SDK 覆盖 SSE、普通响应和完成原因，避免只有预设字符串的测试遗漏此次故障。
- 每个行动的身份层注入相同固定规则（2 狼、预言家、女巫、2 平民；没有守卫），减少按不存在的角色推理。人类名字按随机分配的真实座位写入。用量中独立统计思考 tokens，但不重复计入 total_tokens。

## Risks / Trade-offs

- [用户显式启用思考可能增加等待和费用] → 默认关闭 DeepSeek 深度思考，仍保留有限重试和预算上限。
- [不同服务支持的参数不同] → 默认仅为 DeepSeek 官方服务开启 JSON 模式并关闭思考；其他服务仅在明确配置时发送可选参数。
- [模型仍可能格式错误或网络失败] → 保留 schema、业务校验及安全降级，日志区分截断与解析错误。

## Migration Plan

重启后旧配置自动使用新默认值，无配置文件迁移。回滚代码即可恢复旧行为；可选字段可从配置中移除。

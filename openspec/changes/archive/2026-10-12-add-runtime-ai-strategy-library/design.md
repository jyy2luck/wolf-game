## Context

参见 proposal.md。已有五个纯提示词入口、视角事件和简短私有策略。当前游戏固定为六人，但用户希望策略基础覆盖未来多人数与猎人等角色。策略设计记录于 docs/ai-strategy-library-design.md。

## Goals / Non-Goals

**Goals:**
- 把策略内容与检索逻辑分离，规则前提和行动阶段可测试。
- 在每次原有请求中提供少量实时参考，保留未知信息与合法误判。
- 将所有已整理角色保存在库中，未来按明确规则检索。

**Non-Goals:**
- 本次不修改六人引擎、增加猎人技能、警长或狼队新的聊天阶段。
- 不新增模型调用、向量库、联网搜索、跨局记忆或最优行动裁决。

## Decisions

### D1. 发布结构化静态库

策略存入 llm/strategy_library.json，包含版本、角色人数矩阵和六十七条卡。卡有编号、角色、行动列表、所需规则能力、触发标签、优先级、行动及调整说明。运行时不解析人类文档；包数据显式纳入 setuptools。保留设计文档作为说明，运行数据作为执行检索的数据来源。

### D2. 用显式规则配置匹配

新增不可变规则配置，提供公开初始人数和狼数、启用角色及明确能力。当前配置映射真实六人规则。没有明确声明的能力视为不满足；扩展角色在实际规则未启用时不进入检索。人数矩阵的普通二阵营表在不兼容规则下改用规则专用提醒。

### D3. 仅从合法视角计算局面

使用真实角色、存活座位及可见的死亡、放逐、自身查验和刀口计算确认阵营集合及保守狼数候选。玩家发言不用于硬认证。普通六人规则下单名夜间死者为好人的推断需显式规则能力；未知或冲突资料保留不确定，不修补全知状态。狼队视角使用已揭示队友；死亡队友从当前人数剔除。局面风险区分可能与确定，不把候选中最危险分支写成事实。

### D4. 检索有界且随行动更新

始终保留共同事实和人数原则；其余卡按真实身份、阶段、规则与触发条件排序，最多八张，参考段最多四千字符。返回一个角色人数指导，加上有限卡的行动和退出条件。第一夜探索、有查杀、解药耗尽、本人被刀等能改变排序或过滤。策略是建议，不替模型选目标。

### D5. 接入原有请求

五个提示词在情境层追加策略参考，不改变 JSON schema、事件、权限或重试。模型在原有私有摘要中可简短记录所用打法和切换条件；不新增公开策略编号。检索失败回到简短基础建议，保证对局继续。

## Risks / Trade-offs

- [策略内容与说明漂移] → 检查所有编号、十个角色的人数覆盖和内容与设计的对应；后续策略修改以执行数据为准并同步说明。
- [误把推测写成事实] → 不解析发言认证身份，私有事件按实际可见者与角色读取，候选冲突降级未知。
- [扩展板子误用六人推断] → 规则前提显式匹配，非普通人数规则不输出该结论。
- [数据损坏或打包遗漏] → 校验库、失败降级并验证构建安装后的资源。
- [指导不等于模型真的增强] → 离线测试验证检索和接入；真实对局效果需要后续观察，不能用 mock 胜率作证明。

## Migration Plan

新增模块与包数据，接入提示词，新增局面和集成测试，更新 README。运行无额外配置。移除提示词策略段即可退回原决策路径；没有持久数据迁移。

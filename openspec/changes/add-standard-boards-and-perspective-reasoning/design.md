## Context

动机与范围见 proposal.md。本设计基于当前代码以及已完成、尚未归档的 `improve-ai-decision-quality` 行为；主规格尚未同步的两轮交流、个人票型屏障、行动摘要更新和狼队共享计划均需保留。

现有策略模块具备规则能力标签和十类身份资料，但执行引擎只支持四身份六人局。角色分配、六人容量的人设池、目标输出、身份声明提取、引用校验、规则提示词和终端开局文案均有固定人数假设。当前硬事实闭合只适用于固定二阵营人数胜利；新板子不能继续套用该条件。

## Goals / Non-Goals

**Goals:**

- 用同一份板子定义驱动引擎、玩家界面、合法行动和 AI 公开规则上下文。
- 三种新板子可由一名人类与其余 AI 完整游玩；以开放策略和有限换位推演改善行动选择。
- 把严格成立的推断与有依据的行为预测分开，支持新增人数、规则和角色时扩展已有能力。
- 对保留的六人预设和已有模型配置保持兼容。

**Non-Goals:**

- 本次不增加狼王、白狼王、情侣或其他第三方角色的执行能力；接口保留胜利目标与技能窗口的扩展点，未支持规则不能默认为二阵营人数规则。
- 不穷举所有私有经历、不构造无限递归的互相猜测、不要求玩家最优或每轮欺骗。
- 不增加联网多人、跨局学习或独立规划模型；当前终端交互形式继续使用。

## Decisions

### 1. 板子配置是规则的唯一来源

新增引擎所属的不可变板子注册表。每个定义包含稳定编号、版本、角色数量、阵营与神民分类、胜利条件、技能细则、信息公开规则和阶段调度规则。引擎使用完整规则定义；AI 与 UI 使用其公开投影及调用者合法可见状态。实际座位身份表、他人资源和未公布夜间结果不进入公开投影。

启动增加 `--board`，支持下表四种预设；不指定时沿用原六人预设。继续提供 `--seed`、`--mock`、`--record` 与原模型配置。初始数量来自角色表合计，不另外保存容易漂移的人数值。非法板子、角色处理器缺失或人数不匹配在开局前失败。注册新定义需通过一致性验证，不按一个人数值自动猜测角色配置。

| 编号 | 名称 | 角色配置 | 胜利规则 | 警长 |
| --- | --- | --- | --- | --- |
| `six-classic` | 原六人局 | 狼人2、预言家1、女巫1、平民2 | 原人数胜利 | 无 |
| `nine-standard` | 九人预女猎 | 狼人3、预言家1、女巫1、猎人1、平民3 | 屠边 | 无 |
| `twelve-standard` | 十二人预女猎白 | 狼人4、预言家1、女巫1、猎人1、白痴1、平民4 | 屠边 | 有 |
| `twelve-guard` | 十二人预女猎守 | 狼人4、预言家1、女巫1、猎人1、守卫1、平民4 | 屠边 | 有 |

不采用各模块维护人数和规则分支的方式，以免策略参考与实际结算出现不同版本的规则。

### 2. 三种新预设采用明确的规则变体

以下是本程序的具名预设规则，不宣称各线下团体或平台都采用这些细节。规则数据和开局说明必须完整呈现，后续可新增不同版本预设。

| 规则 | 三种新预设 | 原六人预设 |
| --- | --- | --- |
| 狼刀 | 一夜一个目标，允许刀自己或队友，也允许空刀 | 只可刀好人，不能空刀 |
| 女巫 | 解毒各一次、同夜不能双药、仅首夜可自救；解药用尽后不再获得新刀口；空刀夜仍可用毒 | 保留已有自救、刀口可见和用药行为 |
| 守卫 | 可自守、可空守，不能连续两夜守同一非空目标；空守中断连守限制 | 不启用 |
| 防护 | 守护仅抵挡狼刀；守护和解药同时命中同一狼刀目标时该目标死亡；毒药不受守护或解药抵消 | 原解药结算 |
| 猎人 | 被狼刀、放逐或猎人枪击死亡后可开枪或弃枪；中毒不能开枪，毒与其他死因并存也禁止开枪 | 不启用 |
| 白痴 | 首次被放逐公开翻牌、免死并永久失票，此后不能成为放逐目标；仍可发言，仍计为存活神职，可被夜刀或毒杀 | 不启用 |
| 公开信息 | 常规死亡和放逐不翻牌、不公布私有死因；真实开枪和白痴翻牌形成公开身份事实；夜间死亡名单按座位排序，不编码死因 | 保留原公开记录语义 |
| 遗言 | 首夜死亡者和白天放逐死亡者各一次；后续夜间死者及被枪带走者无遗言；猎人先处理开枪，再处理其原死亡对应的遗言 | 无 |
| 放逐平票 | 正得票最高者并列时一次 PK 发言及复投；PK 候选不投票，再平则无人出局；全弃票直接无人出局 | 平票直接无人出局 |

白痴翻牌不消耗生命、不触发遗言或死亡技能；当日放逐机会已经使用，之后按调度进入夜晚。白痴若持警徽，在翻牌失票时警徽自动撕毁，不保留加权票或转交机会。

### 3. 夜间结果使用待结算批次，死亡反击完成后判胜

夜初存活者按守卫、狼队、预言家、女巫的顺序产生私有行动；所有夜间死亡统一结算，被刀或被毒者仍执行其当夜已经拥有的行动窗口。女巫看到的是规则允许的狼刀信息，不获得守卫目标或实际保护结果。

内部保留死亡原因集合、待触发技能和原始死亡来源。对外只按规则公布信息。猎人资格由引擎判断，不能凭自称身份调用；是否有枪私下告知实际猎人，真实开枪才公开揭示身份，弃枪不公开私有死因。

处理顺序为：公布本批死亡 → 处理合法猎人枪及新增死亡 → 处理该批允许的遗言 → 处理失效警徽 → 到判胜点。待枪或其他已定义结算未完成时不执行最终判胜；技能目标从当时实际合法对象中选择。自刀、毒刀重合等情况按死亡原因集合判断，不按事件写入先后猜测。

新板子在判胜点按以下顺序结算：狼全部出局则好人胜；否则平民全部出局或神职全部出局则狼人胜。两边条件在完整结算中同时成立时，狼全灭优先。狼人数不少于好人数本身不终局。原六人预设保留原胜利规则。

不通过逐个减员即时判胜实现批量死亡，否则会跳过猎人反击或在同一夜中间提前结束。

### 4. 十二人警长流程有独立阶段和投票屏障

用户已选择十二人有警长、九人无警长。首夜行动完成后，先举行警长竞选，再公布首夜死讯和处理死亡技能；未公布的夜间结果只保存在引擎内部。

- 报名按夜初公开存活名单收集，全部结束后统一公布。首夜待死亡者可以报名、警上发言和当选；候选发言按公开座位顺序调度，不使用尚未公开的死者位置安排起点。
- 候选依次一轮发言，之后统一收集退水决定。全部退水则无警长；只剩一人则直接当选。
- 多名候选时，仅最初未报名的警下玩家有竞选投票资格，退水者不取得该次警下投票资格。每张有效竞选票为一票，不使用放逐加权票。
- 为避免提前泄露首夜死者，先按公开名单收集警下选票，再由引擎剔除本夜实际死亡者的无效票；实际投票资格和个人明细在首夜死讯公布后统一披露。模型不能读取此前提交的选票或私有死亡状态。
- 最高票平票时，并列候选进行一次 PK 发言并由原警下有效选民复投；再次平票、没有有效选民或全部弃票均无警长，不无限重选。
- 首夜当选者死亡时，完成死亡技能后选择把警徽交给一名存活且有投票权的玩家，或撕毁。此后警长死亡同样处理；撕徽后本局不重新竞选。
- 在每日放逐发言前，存活警长选择顺时针或逆时针，从其相邻存活座位开始、警长最后发言；首轮和回应采用相同顺序。无警长时沿用公开死者下家起发规则。
- 放逐票中警长为 1.5 票，其他有票者为 1 票。内部使用整数票权单位 3 与 2，展示时还原，避免浮点平票误差。白痴翻牌后不收集其投票，也不把口头意向计为票。

报名、退水、选举投票和放逐投票各有自己的收集屏障与公开事件。警上、PK、回应、遗言等使用明确阶段及发言窗口，不复用含混的“当日已经说过话”状态。

### 5. 合法行动由引擎提供，人数和座位从上下文验证

引擎为每个窗口提供行动类型、调用者、公开存活状态、合法目标、票权和是否处于待结算状态。猎人开枪、首夜待死亡者竞选发言、死亡警长移交警徽和遗言是显式授权的特殊窗口，不要求调用者仍在普通存活集合。

保留原五类回调的兼容入口，扩展守卫、猎人、警长报名/退水/投票/方向/警徽及遗言接口。缺少新角色所需处理器时在开局前报错；原六人测试和调用者无需提供不会发生的技能接口。

所有目标与引用座位改为正整数解析加当前窗口集合验证。空刀、空守、弃票、退水与委托队友使用明确的动作含义，不混用同一个空值。声明提取支持多位数座位且保留否定、条件句、引用转述的排除。规则提示词、胜利目标和技能说明从公开板子生成；实际完整记忆继续来自本人过滤事件。十二人需要十一套互异人设，姓名和风格不参与身份认证。

### 6. 策略角色标签用于描述知识，技能需求用于验证执行

策略数据升级为可兼容迁移的新版本。保留稳定编号，给策略补充用途、相关决策窗口、所需技能、可观察线索、其他角色可能回应、失败代价、关联反制和退出条件。已有规则前提继续适用；人数指导增加胜利规则前提，不能将原人数局的四人/三人结论直接显示在屠边局中。

所有角色共享完整策略知识，不按真实角色设置阅读白名单。每次检索仍只提供有限相关内容，分为共同依据、本人候选方法、他方可能打法与可用应对。通用表达和伪装方法可以跨角色借用；技能执行受真实权限、资源和引擎合法目标约束。

本人行动过滤与他方参考过滤分别进行：狼人选刀时可以获得女巫用毒、守卫防护、猎人反击的参考，但这些是对方的可能行动。对方资源未知时形成有条件参考，不把本人没有毒药解释成他方也没有毒药。未启用的角色可作为库内知识存在，不进入本局有效技能分支。

参考段维持固定条目和字符预算，为本人行动和他方回应分别保留空间，避免通用卡或某一阵营卡挤满全部位置。基础事实约束始终保留，完整原始记忆不因参考预算而被替换成策略摘要。

### 7. 严格推断与行为预测分开

局面对象区分已确认事实、公开声明、条件假设和行为预测。对方视角以公开历史加假设身份对应的信息能力构造，不读取对方实际私有事件或个人摘要；本人私有事实可约束候选局面，但不自动成为其他玩家相信的公开证据。

只在所需规则和时点成立时应用规则推断。允许自刀后，女巫真实刀口不再直接认证好人；允许空刀或存在守卫时，平安夜不能认证用过解药。死讯数量必须区分夜间原始结算与后续枪击等来源，不能用总死亡人数简单推断毒药。

新板子根据公开角色数量、神民分类、已揭示身份、本人结果和屠边继续游戏约束维护可行范围。保留精确且可解释的约束传播；小规模时可完整检查候选，规模变大时优先用计数约束和带剪枝的可满足性检查。不得将完整角色与私有经历的所有组合物化。

有计算上限的候选预测可以截断，但只有完备检查或逻辑证明才能认证阵营和资源。“抽到的所有分支都说某人是狼”不构成确定事实。规则未知、资料矛盾或推断未完成时保留未知，并让对局继续。

### 8. 复用现有行动调用，推演到一次回应和一次调整

每次决策围绕当前冲突选择最多三名关键玩家、最多三种有出处且互相兼容的主要解释、最多三个本人候选行动。分别检查他方目标、可见信息、可能技能、下一次合法行动窗口和预期回应，再比较本人可调整方案。没有具体行为信息的首夜采用少量规则与资源分支，不给所有玩家编造心理画像。

同阵营玩家也属于需要理解的对象：真预言家的结果不等于其他好人已经相信；狼队共享夜间计划不等于白天能即时私聊。不同解释使用定性可信程度，不由未校准模型编造精确胜率。符合某张狼人卡不能直接认证狼人；允许好人试探、站错边和对方不按最优策略行动。

在原行动请求中完成选择，不增加独立检索或规划请求。公开输出保持口语化，仅表达本轮需要的依据、问题与行动方向。私有摘要增加可选的简短他方预判和改策条件，保留原 assessment/goal/claim；不输出长篇思考过程。旧响应仍可解析，成功校验后才提交新摘要；失败候选不能污染记忆。实际事件出现后核对预判，失效的假设及时撤销。

### 9. 按真实冲突细化策略和评估

首批细化场景包括：真假预言家争取摇摆票、假金水和倒钩、狼队切割、合法自刀产生的银水解释、猎人真假身份及毒枪差异、白痴翻牌后的票权、守卫预测刀口与同守同救、警长竞选与警徽经营、屠边保护最后一类好人和投票后计划切换。

策略卡给出成功条件、可观察信号、典型回应、失败代价与反例，不按打法名称强制套招。多狼计划明确分工、目标票和公开改策信号，仅在合法狼队窗口共享；不得合并队友个人摘要。

验证分三层：规则与视角不变量；跨板子固定局面；四种预设的完整离线流程。固定局面使用相同公开记录、不同合法私有信息或规则的成对案例，验证参考与行动任务变化。真实模型评估作为后续可选实验，按板子、座位和角色记录有效回应、关键票、资源判断、预判修正、重试及成本；离线通过不等于胜率得到证明。

## Risks / Trade-offs

- [标准板子在平台之间存在规则差异] → 在具名预设、版本和开局说明中明确本程序变体，规则变化使用新配置版本。
- [首夜竞选提前泄露死亡或投票] → 暂存夜间结果、分离公开名单与实际结算资格、选票屏障及延后披露个人明细，增加视角成对验证。
- [屠边、枪、警徽和白痴失票相互影响] → 统一阶段调度、死亡队列与实际票权，仅在完整结算点判胜。
- [跨视角参考变成全知推断] → 事实和假设使用不同数据类别与标识，公开投影不接受他方私有状态，测试同一可见输入下隐藏状态变化不改变输入。
- [人数增加导致候选和 token 膨胀] → 约束传播、完备性标记、重点人物与分支预算，保持参考长度限制，不增加规划请求。
- [同一模型推演容易预测所有人都按同样套路行动] → 允许多种有依据解释和失误，优先使用实际发言、票型及局内行为，发现反证后更新。
- [范围跨越多模块，旧规格与已完成变更尚未同步] → 以当前已实现行为为迁移基线，实施前核对两份规格的交集；本变更不自动归档其他变更。

## Migration Plan

1. 引入板子注册表与公开规则投影，把原六人规则完整注册为兼容预设，再接入动态座位和角色分配。
2. 实现阶段调度、三种新增角色、屠边与警长规则，并为人类、离线代理和 AI 统一提供合法行动窗口。
3. 升级策略资料和检索用途，接入有限换位推演及可选私有摘要扩展，保留已有成功提交、重试和降级流程。
4. 更新启动选择、规则展示、人设容量和公开记录；记录包含板子编号、规则版本与公开规则快照，避免日后按错误规则解读。
5. 完成各层验证、打包检查和严格规格校验。原模型配置无需迁移；无持久对局恢复格式需要迁移。回滚时原六人预设与旧配置仍可使用，新板子记录按版本保留为历史资料。

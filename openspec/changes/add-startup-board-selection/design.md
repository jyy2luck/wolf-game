# Design

## Context

参见 proposal.md 的动机。`engine.boards.BOARDS` 已注册全部四个板子，`build_game` 按所选板子分配人数、角色和 AI，现有完整离线测试覆盖这些玩法。当前 `--board` 默认 six-classic，普通启动无法发现其他选择。终端已有 Rich 表格与能恢复损坏 UTF-8 的统一输入方法。

## Goals / Non-Goals

**Goals:** 将选择结果接入现有建局链路，确保选择前不会配置连接或分配角色；显式板子参数继续支持自动化。

**Non-Goals:** 不新增板子、规则、额外的“人数→板子”二级菜单、配置持久化或新依赖，不变更终局统计与记录格式。

## Decisions

- `--board` 未提供时为 None；`main` 在原有异常处理与日志范围内调用 `TerminalUI.prompt_board`，将返回的板子编号写回参数后调用 `build_game`。菜单不构造 Game 或 LLMClient，配置取消不会留下半局状态。相比在建局函数内提示，这样可保持直接调用建局函数的测试与脚本无需交互。
- 菜单作为类方法，复用 `_read_input` 与 Rich Table；按注册表顺序展示四项，角色数量与警长状态直接取自 Board，避免复制规则或把两种十二人玩法混为一项。空输入对应第一项六人；编号以字符串集合校验，避免非数字、越界与特殊 Unicode 数字触发转换错误。
- 保留 `build_game` 未提供板子时的六人回退（包含 None），不影响其既有直接调用方。不根据 isatty 静默跳过菜单：管道输入也可完成选择，自动化用显式 `--board` 控制输入。
- Ctrl-C 与 EOF 共用入口的正常中断分支（状态码 130），日志照常关闭保存；不输出技术堆栈。不另加菜单取消状态或配置项。
- 以全板子参数化测试覆盖菜单默认值、合法与非法输入、参数绕过及选择后真实建局/记录；继续运行原有全板子完整 mock 对局。入口夹具显式提供板子，避免统计和日志测试被新输入阻塞。

## Risks / Trade-offs

- [已有脚本未传 --board 时输入会错位] → README 标注新增输入步骤与显式参数绕过方式；--help 同步说明。
- [九/十二人局的调用与成本高于六人局] → 菜单明确人数，沿用现有用量统计，不增加模型请求。
- [菜单表格在窄终端换行] → 使用 Rich 自适应列宽与普通文本信息，验证常见 80 列输出可读。

## Migration Plan

无需配置或存档迁移。与代码同时提交提案、规格、任务及验证记录；回退此提交即可恢复原启动行为。

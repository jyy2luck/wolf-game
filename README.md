# 🐺 LLM 狼人杀（llm_murder）

终端单机狼人杀：**1 名人类玩家 + 其余 LLM 玩家**，支持原六人、九人和两个十二人板子。打开终端即可开局，AI 玩家有性格人设，会依据可见信息判断局势，也能假跳身份、试探和误导其他玩家。

- 规则判定 100% 由确定性引擎完成，LLM 只负责「表演」（发言、投票、技能决策）
- 玩家与 AI 共用同一套视角隔离机制，信息绝对公平
- 启动时选择六人局、九人预女猎、十二人预女猎白或十二人预女猎守，回车默认六人局；具名规则版本由引擎、AI、界面和记录共用

## 安装

需要 Python ≥ 3.11。推荐使用 [uv](https://docs.astral.sh/uv/)：

```bash
uv sync            # 创建虚拟环境并安装依赖
```

或使用 pip：

```bash
python -m venv .venv && source .venv/bin/activate
pip install openai rich pydantic pytest
```

## 配置

首次启动选定板子后会进入交互式引导，依次填写 OpenAI 兼容配置：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| base_url | `https://api.deepseek.com/v1` | 任何 OpenAI 兼容服务（DeepSeek / Qwen / OpenAI 等） |
| api_key | — | 输入不回显；自备 |
| model | `deepseek-chat` | 可修改 |

- 配置写入前会发起一次最小连通性请求验证，**通过才落盘**
- 配置保存到 `~/.llm_murder/config.json`，POSIX 系统权限为 600（Windows 不使用 POSIX 权限位），绝不写入项目目录
- 之后启动自动加载；`--reconfig` 可重新配置

旧配置无需修改，重启即采用新的生成预算。可在 `~/.llm_murder/config.json` 中增加以下可选字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| max_tokens | `4096` | 单次输出基础预算；截断可在当前行动内扩容，后续行动恢复基础值 |
| max_tokens_limit | `16384` | 所有游戏请求的预算上限，不能小于 max_tokens |
| thinking | `null` | 兼容旧字段；本版本全局关闭思考，旧的 `"enabled"` 也不再开启 |
| json_mode | `null` | DeepSeek 官方服务自动启用 JSON 模式，其他服务默认不启用；可显式设为 `true` 或 `false` |
| max_input_tokens | `12000` | 全部请求消息的输入软预算，包含纠正和回查内容；使用偏保守估算 |
| context_window_tokens | `null` | 仅在核实服务模型窗口后填写；预检扣除当前输出预算与 512 tokens 余量 |
| action_timeout_seconds | `90` | 每个行动的总时限，涵盖网络、流式读取、退避和纠正 |

所有行动全局关闭深度思考：DeepSeek 官方端点或已显式配置 thinking 的兼容端点发送 `disabled`；其他端点不发送未知扩展参数，仍需在服务端关闭其默认思考或选择非推理模型。旧配置不重写。4096/16384 是应用的输出预算，不代表模型上下文容量，也不是每局累计额度。

每个行动最多发起三次实际请求；网络、输入超限、输出截断、格式/事实纠正和回查共享次数及总时限。不可重试的鉴权/参数错误立即降级；输入超限会缩减活跃历史再尝试，输出截断只在当前行动内扩容，不把半截 JSON 加回历史。


## 运行

```bash
uv run python main.py             # 先选择游戏，无配置则继续引导
uv run python main.py --reconfig  # 重新配置 LLM 连接
uv run python main.py --mock      # 离线演示模式（不调用真实 LLM，验证流程）
uv run python main.py --seed 42   # 固定角色与座位随机种子（模型输出仍可能变化）
uv run python main.py --record game.json  # 终局保存公开记录，不覆盖已有文件
```

未传 `--board` 时，启动菜单先展示四种玩法的人数、角色配置和警长开关。输入 1～4 选择，直接回车默认原六人局；非法输入会提示重选，Ctrl-C 或输入结束退出。离线 `--mock` 模式也会显示菜单。

四种预设（本程序规则版本 v1，具体规则可能与其他平台不同）：

| 菜单编号 | `--board` | 角色配置 | 胜利条件 | 警长 |
| --- | --- | --- | --- | --- |
| 1（回车默认） | `six-classic` | 2狼、预言家/女巫各1、2民 | 狼全灭好人胜；狼数≥好人数狼人胜 | 无 |
| 2 | `nine-standard` | 3狼、预言家/女巫/猎人各1、3民 | 屠边 | 无 |
| 3 | `twelve-standard` | 4狼、预言家/女巫/猎人/白痴各1、4民 | 屠边 | 有 |
| 4 | `twelve-guard` | 4狼、预言家/女巫/猎人/守卫各1、4民 | 屠边 | 有 |

显式传入 `--board` 会跳过选择菜单。脚本或预先准备的对局输入应指定该参数，避免新增菜单输入导致后续内容错位；`--mock`、`--seed`、`--record` 可继续组合使用：

```bash
uv run python main.py --board six-classic --mock --seed 42
uv run python main.py --board nine-standard --mock --seed 42
uv run python main.py --board twelve-standard --mock --seed 42
uv run python main.py --board twelve-guard --mock --seed 42 --record guard-game.json
```

三种新板子采用屠边：狼全灭优先判好人胜，否则平民或神职全灭判狼人胜；狼好人数相等本身不终局。所有死亡反击、遗言和警徽处置完成后才判胜。

- 夜间按守卫（若启用）→ 狼队统一选刀 → 预言家 → 女巫调度，夜初存活角色完成当夜窗口后统一结算。新板子允许自刀、刀队友和空刀；女巫仅首夜可自救，解药耗尽后不再获得新刀口，空刀夜仍可用毒；各药一次，同夜不能双药。原六人保留只能刀好人、不能空刀、可自救和耗尽解药后仍见刀口的规则。
- 守卫可自守或空守，不能连续两夜守同一非空目标，空守中断连守限制。守护只挡狼刀；同守同救致死，毒药不受守护或解药抵消。
- 猎人因狼刀、放逐或枪击死亡可开枪/弃枪；中毒及含毒混合死因禁止开枪。真实开枪公开身份，弃枪不公开死因。猎人先枪后原死亡对应遗言，枪击目标无遗言。
- 白痴首次放逐翻牌免死并永久失票，后续不能成为放逐目标；仍可发言、计为存活神职，可被夜刀/毒杀。持警徽时翻牌自动撕徽。
- 新板子首夜死亡和白天放逐死者各一次遗言，后续夜死无遗言；常规死亡/放逐不翻牌、不公开私有死因，新板子夜死名单按座位排序。原六人无遗言。
- 十二人首夜死讯前竞选：统一报名公示→警上发言→统一退水→原警下投票。待死亡者可参选和当选，但选举票只有原警下且实际存活者有效；退水不增加选举票权，资格和个人明细死讯后披露。单候选直接当选，全部退水/无有效票/全弃票无警长，最高平票一次PK及复投，再平无警长。
- 警长选择顺/逆时针，从相邻存活者起发、两轮均最后发言；放逐1.5票，其他有票者1票，内部使用整数3/2单位。死亡警长在技能和遗言结束后移交给存活有票者或撕徽，此后不重新竞选。
- 白天首轮发言→简短回应→统一收集选票→公布个人票型。新板子正票最高并列时一次PK和复投，候选不投票，再平/全弃票无人出局；原六人平票直接无人出局。

输入约定：白天发言为多行输入（单独回车结束）；技能与投票为受限选项输入（支持10～12号，非法输入重输）。0在对应窗口明确表示空刀、空守、弃枪、弃票或撕徽；狼人输入d表示委托存活AI队友，与空刀不同。警长报名/退水用y/n，方向用1/2。
终端支持中文行编辑；若输入含无法解码的字符，会提示重输当前行，保留此前已输入的发言行。

发言顺序由引擎统一提供给 AI：例如 5 号死亡后，当天顺序是 6、1、2、3、4。
6 号首位发言时，已发言集合为空，1、2、3、4 号尚未轮到；轮到 1 号时，6 号已完成，2、3、4 号仍在等待。
“尚未轮到”只描述今天的流程，不能据此指控玩家故意沉默，也不表示他在往日没有发言。
平安夜沿用既有起点，无既往死者时从 1 号开始；有既往放逐则沿用其下家，多名夜间死者时以首位死者为起点。

每位存活玩家每天都有首轮发言和一次简短回应。回应能读取全部首轮观点，针对后置指控或新证据调整站边；两轮都按相同顺序执行，编号全局递增。

AI 的发言、投票和夜间行动以本局完整可见事件为记忆来源，包括人类和 AI 的公开发言。输入未超预算时发送完整历史；超过时保留可见事实、带编号的旧发言节选及优先保留的最近六条原文。冗余板子/阶段标签不重复发送，狼队主观计划使用最新版本。
每条记忆标明天数、昼夜与来源（系统公开事实、角色私有事实或玩家声明）；已出局玩家的发言仍保留。
例如第 2 天可引用“第 1 天 2 号在 [#3] 说过……”；2 号今天尚未轮到不影响这个真实历史编号的有效性。
需要旧原文时可先返回 `{"recall":[编号]}`，每行动最多一次、最多三条，仍占用同一请求预算。节选不认证身份或查验；完整原文继续保存在本地供回查和事实校验。自身最近三条发言只辅助保持立场；新局重新创建事件和 AI 状态，私有信息继续按角色视角隔离。
玩家说过某句话只证明其声明存在，不证明句中指控属实；当前对局在全部投票结束后统一公布每人的目标或弃票，可对照公开站边；旧记录只有总票数时仍不能猜定个人票型。

所有角色都可以假装其他身份或阵营、假认狼、编造自己的查验与用药经历，以帮助真实阵营获胜。
可以选择性引用真实发言、夸大嫌疑或歪曲动机；不能伪造原话、编造他人的公开行为，或把正常轮候说成故意沉默。
例如“我是预言家，昨晚验了3号”可以是骗局；但2号整局尚未发言时，说“2号刚才长篇大论”会被拦截。
AI 会在每次发言、投票和夜间行动的原请求中生成并更新简短私有策略摘要，区分真实判断、本轮目标和公开说辞，供后续发言、投票与夜间行动参考。
摘要是可修正的主观策略，不能替代真实事件；投票可以不同于公开攻击对象，假跳也不会获得真实技能权限。
摘要按玩家和对局隔离，只有调用者自己可用；允许策略失败，不要求每轮撒谎或每步最优。

AI 每次发言、投票、狼刀、查验和用药都会自动查阅本地策略库：按真实身份、当前存活人数、
行动阶段、当局规则和自身可见资源分别检索本人方法与他方条件参考，合计最多 8 条策略，参考段最多 4000 字符。
例如女巫有解药时比较救人与毒人，解药耗尽且三人残局不用药会判负时提高危急用毒的优先级；
预言家取得真实查杀后，发言与投票会获得对应信息发布和带队策略。
硬事实仅按当前板子与完整判胜点推断：原六人人数局三人残局中自身与刀口或真实金水均为好人时，可认证第三人为狼；新板子允许自刀，刀口不认证好人，屠边局也不能直接套用人数残局表。明确身份、查验声明以原始编号供核对，对跳、被查杀与刀口信息冲突才触发对应策略；声明不作硬认证。

每次查询使用最新可见事件和人数，未知狼数保留候选；严格检查只遍历狼座位组合、以计数区间检查神民容量，最多5000个组合，截断不能认证身份。他人的身份、查验或药量声明不会变成确定事实。
检索在本地完成，直接加入原有请求，不增加模型调用；策略是行动参考，最终目标仍由 AI 结合局势选择。

执行数据位于 `llm/strategy_library.json`，版本2保留原67个编号并增至71条策略，含10类身份的人数指导；
设计说明见 [AI 策略库设计](docs/ai-strategy-library-design.md)。角色标签描述知识，所有角色可阅读相关打法；
真实技能执行只由引擎授权。特殊狼和第三方角色的库内知识不代表本局启用了这些角色。
可修改执行数据中的行动、优先级、规则前提和触发条件；库在进程内缓存，修改后重启游戏生效。
文件缺失或损坏会降级为基础参考，对局继续。策略参考和私有摘要不在终端公开展示。

AI 生成和重试期间显示发言人及“生成与校验中”状态；通过格式、目标和事实校验后，
由正式事件一次展示完整正文：编号、姓名、座位与发言窗口独立成标题并加粗着色，正文另起一行沿用终端前景色，发言块间留空行。候选发言、原始 JSON、`references` 和 `private_strategy` 不展示给玩家。
失败时同样结束等待，按正式事件展示中性兜底，然后继续发言和投票。
存活名单与板子、阶段、警长摘要仅在首次出现或内容变化时更新，游戏事件及自己的角色私有提示仍照常展示。

## 单局成本预估

每个白天，每名存活 AI 各进行一次首轮发言、一次短回应和一次投票；夜晚由夜初存活神职及狼队分别行动；新板子增加守卫、死亡猎人、遗言和警长实际窗口，竞选/PK也会增加调用。狼队仍用一次共享选刀，不随狼人数逐狼加规划请求。有限换位推演在原请求内比较最多三名关键玩家、三种解释和三个候选行动，不新增模型调用。调用串行，思考和重试会增加等待与 token 消耗，实际成本依模型及对局长度变化。终局显示调用次数、输入/输出/思考用量，以及结构化重试和降级次数。

`--record game.json` 保存格式版本2、板子编号/规则版本/公开规则快照、公开正式历史、终局已揭示身份、模型名、种子和统计，每次请求的估算/实际输入输出、思考/缓存 tokens、耗时、错误类别与校验结果，内部座位号从 0 开始，弃票为 null。记录不包含密钥、夜间私有事件、AI 私有摘要或失败候选，已有文件不覆盖。可用真实对局检查有效回应、关键归票及降级频率；离线测试验证流程和固定局面，不能证明实战胜率。

## 设计要点

- **事件溯源**：对局一切信息以事件流表示，玩家「记忆」= 视角过滤后的子集（纯函数），人类与 AI 同机制
- **发言依据**：发言包的 `references` 提供真实发言编号、座位、天数与原文片段，正文使用对应 `[#n]`。系统同时核对依据与正文，允许跨天及已出局玩家引用；旧包缺少字段按空列表处理，无引用发言仍需接受事实校验
- **发言长度**：去除首尾空白后，首轮及警上正文最多 240 字符，回应/PK/遗言最多 150 字符（含标点、空格和引用编号）。超长时反馈长度错误，要求模型缩写并同步调整引用，再核对完整正文；不直接裁切，避免半句话和引用标记丢失。长度纠正同样占用既有的最多三次总尝试
- **表达策略与事实边界**：真实身份只决定阵营目标和技能权限，公开身份、自己的私有经历和动机解释可以是策略性说辞。检查明确的无记录行为、时间错置、不可见表情动作及死亡、得票断言的直接冲突；保留等待、条件假设、主观怀疑与有真实依据的反驳转述。自然语言检查只覆盖明确句式，不能证明任意转述或推理都正确
- **私有策略**：各行动包可包含 `private_strategy`（assessment 当前判断、goal 本轮目标、claim 公开说辞，分别最多120、60、120字；可选prediction预判≤180字、switch_condition改策条件≤120字）。`suspect` 表示公开怀疑对象，不等于真实判断。摘要只在对应行动通过全部校验后更新，旧包省略或填 null 时保留此前摘要，新局清空
- **有界纠正**：发言格式、目标、事实、摘要格式和截断共享首次加最多两次重试。截断（`finish_reason=length`）在现有 token 上限内扩容，网络重试及原文回查也共享三次实际请求与行动总时限。最终失败只使用“目前依据不足，我暂时保留判断。”，公开怀疑未定、情绪平静；失败候选不更新私有策略，此前已接受摘要仍保留。投票与技能仍有安全降级
- **狼窝合议**：不同存活狼人数共享一次调用统一刀口，同时返回可选的白天分工、归票和退出计划。计划通过狼队私有事件共享，标为可调整的主观策略，不共享队友个人摘要；人类自行选刀时不增加规划调用


预判是主观状态，不是硬事实。下一行动对照最新正式发言、票型与技能事件核对：同阵营未必相信真实结果，预期支持者也可能改票；好人可能试探或伪装，对手可能误判和采取非最优回应。已完成最后发言者无法再回答，不能视为回避。省略新增预判字段保留旧值，失败候选不提交，新局清空。

离线验证覆盖四预设完整对局、人类新角色输入、规则矩阵、相同可见输入下隐藏状态变化、策略成对局面、有限推断与成功提交边界。离线模型只返回合法演示行动，确定性测试代理也不代表真实模型决策质量。真实 API 验证结果见 docs/context-budget-validation.md；这些对局用于检查耗时、预算与降级，不评估胜率。人数、警长与技能窗口会增加实际调用次数和整局耗时。


## 自动对局与诊断

```bash
uv run python scripts/benchmark_games.py --output /tmp/wolf-benchmark
uv run python scripts/benchmark_games.py --mock --boards six-classic nine-standard twelve-standard twelve-guard --seeds 42 43 --output /tmp/wolf-offline
```

脚本沿用正式 Controller 和每个角色自己的视角，全部座位交给 AI，单局串行。默认跑 6/9/12 人三局，每局最多 10 天；超限写为 `max_days`，不伪造终局。输出文件不覆盖，重复运行请换目录。`summary.json` 给出单次请求 p50/p95/最大耗时、总 tokens、截断、输入超限、超时、校验错误和降级次数；每局 JSON 保存安全请求指标与公开记录。

交互式游戏默认将运行诊断逐条写入 `~/.llm_murder/logs/<时间戳>-<唯一后缀>.log`，过程不打印请求、校验、重试和降级详情；终局仍显示完整调用与用量统计，并提示日志路径。Ctrl-C 或异常退出也保留已写日志并提示位置；日志创建或写入失败只提示一次，游戏继续，已有文件会标为不完整。日志目录和文件新建时分别使用 700/600 权限，包含板子、模型、命令行种子、运行模式、安全请求指标及退出状态，不保存密钥、提示词、角色私有事件、私有策略、原始候选或服务端错误正文。旧日志不会自动删除，可在该目录中手动删除不再需要的 `.log` 文件。`--record` 仍独立保存公开 JSON 和请求指标，已有文件不覆盖；自动对局脚本保留原有诊断输出。

日志中的 `output_truncated` 表示输出预算耗尽，`input_context` 表示服务拒绝上下文长度，`action_timeout` 表示行动总时限到达，`validation` 中的错误表示输出未通过格式/事实校验。这些原因需要分别处理。估算并非模型真实分词，且固定事实和当前任务也需占用预算；极长局仍可能安全降级，完整事件不会删除。程序节选无需额外摘要 API，但请求仍携带本次活跃记忆，并非服务端永久会话。
